# 完成收尾工作流

描述一个 Spec 通过最终验收后的收尾步骤。触发条件：最新独立验收为 **PASS**，且用户发起收尾（或确认进入完成阶段）。

## 流程

1. **标记完成**
   - 将 Spec 的 `spec.md` 状态更新为 `completed（已完成）`。

2. **汇总文档**
   - 将本 Spec 产生的过程性 md 文档（各轮验收记录、实施报告要点等）汇总为一个 `summary.md`（建议放于 Spec 目录下）。
   - 汇总内容建议包含：元信息、目标、技术栈、需求清单、接口、验收结果（含各轮历程）、决策引用、使用方式、遗留问题。
   - 汇总文档是「归档」，不得替代 `spec.md` / `plan.md` / `acceptance.md` 的原始记录。

3. **提交代码**
   - 仅在用户明确要求提交后执行 commit / push；未获用户明确同意，即使安全核查通过也不得提交。
   - 提交前必须安全核查：
     - `git status` / `git diff` / `git check-ignore` 确认无密钥、`.env`、`data/`、`.venv/`、`node_modules/` 等敏感或生成物入库。
     - 搜索暂存内容确认无硬编码密钥。
   - 只暂存预期文件，撰写简洁提交信息，commit 并 push。
   - 发现敏感文件一律不提交，先修复 `.gitignore` 或移除。

## 约束

- 收尾仅在最新独立验收为 PASS 后进行。
- 未获用户明确要求，不得 commit / push（即使验收已通过）。
- 提交前未完成安全核查，不得 commit / push。
- 禁止提交密钥、`.env`、数据库、PDF 等敏感/生成文件。
