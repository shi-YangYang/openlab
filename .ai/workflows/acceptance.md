# 验收工作流

描述验收 Agent 的独立验收规范。

## 独立性

- 验收 Agent 与实施 Agent 相互独立。
- 验收 Agent 不得修改业务代码，只能检查、测试与记录。

## 验收依据

- Spec 中的需求（FR/NFR）与 `acceptance.md` 中的验收标准（AC）。
- 相关决策记录。

## 验收步骤

1. 阅读 Spec、决策记录与实施报告。
2. 检查实施结果是否覆盖全部验收标准。
3. 运行测试/验收脚本（`tests/` 目录）。
4. 必要时手动验证功能与边界条件。
5. 输出验收结论：`PASS` / `FAIL` / `BLOCKED`。

## 结论含义

- **PASS**：全部验收标准满足，可进入下一环节。
- **FAIL**：存在不满足项，进入返工流程（见 `rework.md`）。
- **BLOCKED**：存在需用户或外部条件解除的阻塞，返回协调开发 Agent 处理。

## 验收记录

验收结果写入对应 Spec 的 `acceptance.md`。
