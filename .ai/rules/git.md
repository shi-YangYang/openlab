# Git 规则

约束 Git 使用行为。

## 提交

- 仅在被明确要求时才提交、推送或创建 PR。
- 例外：Spec 完成收尾（见 `.ai/workflows/completion.md`）是流程授权的提交场景，该阶段的安全核查通过后即可 commit 并 push。
- 提交前检查 `git status`、`git diff`、`git log --oneline -10`。
- 只暂存预期文件，绝不提交密钥。
- 提交信息简洁、符合仓库既有风格。

## 禁止操作

- 不更新 git 配置、不跳过 hooks、不使用交互式 `-i`、不强制推送、不创建空提交。
- 提交失败或 hooks 拒绝时，修复后重新提交，不 amend 失败的提交。

## 分支与 PR

- 创建 PR 前检查状态、diff、远端跟踪、近期提交及相对基线的差异。
- 审查 PR 包含的所有提交，而非仅最新提交。

## 安全

- 敏感文件（密钥、环境变量等）需通过 `.gitignore` 排除。
