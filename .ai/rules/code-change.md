# 代码变更规则

约束代码编写与变更行为。

## 职责边界

- 协调开发 Agent 不直接编写或修改业务代码（`frontend/`、`backend/`）。
- 实施 Agent 负责编码，验收 Agent 只检查不修改。

## 变更规范

- 遵循现有代码风格与项目约定，复用已有库与工具。
- 修改前先阅读上下文与相关文件，理解现状再动手。
- 不引入未确认的新依赖；如需要，先返回协调开发 Agent 确认。

## 安全要求

- 不得硬编码或提交密钥（LLM API Key、SSH 凭据、数据库密码等）。
- 不得引入暴露或记录密钥的代码。

## 提交规范

- 仅在被明确要求时才提交代码。
- 提交前检查 `git status`、`git diff`，只暂存预期文件，不提交密钥。
- 提交信息简洁，符合仓库既有风格。
