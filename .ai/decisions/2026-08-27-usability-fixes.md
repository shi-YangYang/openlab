# spec-021 功能维护决策

## 决策标题

确定 Semantic Scholar 限流的应对策略、以及三处 UI 可用性修正的方案。

## 元信息

- **日期**：2026-08-27
- **状态**：accepted
- **决策者**：用户
- **关联 Spec**：spec-021-usability-fixes

## 背景与问题

1. Semantic Scholar 搜索再次失败。实测为官方 Graph API 返回 **429 Too Many Requests**（未认证共享配额耗尽），并非代码回退：spec-013 只做了接入，从未处理限流；且聚合器把异常静默降级为外链跳转，用户不知道真实原因。
2. Agent 页消息输入框过矮（minRows=1），长文本看不全。
3. LLM 配置组模型列表中「思考强度」输入框过窄（220px），推理强度值一多内部换行、行高拉长整页。
4. 搜索页两种模式按钮「关键词 / 检索式」「主题描述（LLM 拆解）」表述不直观，普通用户无法区分两种模式的差别；输入框占位提示同样不友好。

## 备选方案（针对限流）

- 方案 A：仅加重试。
- 方案 B：重试 + 可选 API Key 提额 + 把失败原因透传到前端展示。(采用)

## 决策

1. **限流应对**：
   - `SemanticScholarProvider.search` 对 429/5xx/网络错误做最多 2 次重试：优先读响应 `Retry-After` 头（封顶 5 秒），否则指数退避（1s、2s）；重试仍失败则抛出，交由聚合器降级。
   - 新增可选环境变量 `SEMANTIC_SCHOLAR_API_KEY`（settings 注入）：配置后请求带 `x-api-key` 头获得更高配额；`.env.example` 补充说明。
   - 聚合器 `fallbacks` 条目新增可选 `message` 字段（对非登录类异常摘要原因，如「官方限流(429)，已重试仍未恢复」）；`SearchFallback` schema 同步；前端在降级提示里展示该原因。
2. **Agent 输入框增高**：`autoSize` 由 `{minRows:1, maxRows:4}` 改为 `{minRows:4, maxRows:10}`。
3. **模型列表行宽**：该行改为 flex 布局，「思考强度」多值输入改为弹性宽度（最小约 300px 并随行伸展），避免换行撑高；模型 id 与上下文长度保持固定宽。
4. **搜索表单文案**：
   - 模式按钮：`直接搜索`（原样提交各平台）与 `AI 智能搜索`（先把研究主题改写成检索式）；两枚按钮各自包裹 Tooltip 详细解释差异。
   - 输入框 label 随模式变化：「搜索关键词」/「研究主题描述」；占位提示分别改为直白表述（含示例与说明该内容会被如何处理）。

## 理由

- 429 是外部配额问题：重试吸收瞬时抖动、Key 给重度用户兜底、原因透传消除「莫名失败」，三者缺一不可，而成本都很低。
- 其余三项均为低成本纯 UI 修正，不改任何数据结构。

## 影响与后果

- `SearchFallback` 增加 `message` 字段属向后兼容（可选字段）。
- 前端仅 SearchForm/AgentPage/LlmConfigForm/App.tsx 小改；后端仅 semantic_scholar/aggregator/schemas/config 小改。
- 重试会使该平台最坏情况多耗时约 3 秒，聚合器并发下不影响其他平台返回速度。
