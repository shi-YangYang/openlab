# spec-027 代码重构决策

## 决策标题

确定前端样式系统重构（CSS Modules + 公共样式类）与前后端大文件模块化拆分的方案。

## 元信息

- **日期**：2026-08-28
- **状态**：accepted
- **决策者**：用户
- **关联 Spec**：spec-027-refactor

## 背景与问题

1. **前端 212 处行内样式**：大量重复属性（width:100% × 16、marginBottom × 18、textAlign+padding 居中模式 × 9 等），修改一个设计决策需要改多个文件。
2. **大文件**：AgentPage.tsx 1176 行（流式+附件+审批+会话管理全在一个文件）、ServerDetailPage 551 行、ExperimentRunPanel 539 行、LlmConfigForm 522 行；后端 main.py 1631 行（71 个端点全在一个文件）、database.py 1058 行、tools.py 835 行。
3. **可维护性**：行内样式无法复用、无类型检查、无媒体查询支持；大文件改动风险大、review 困难。

## 备选方案

- 方案 A：CSS Modules（`.module.css`）—— antd 兼容、Vite 原生支持、类型安全（可选 typed-css-modules）。
- 方案 B：styled-components —— 运行时开销、包体积增加、与 antd 主题体系割裂。
- 方案 C：纯全局 CSS 类名（BEM 命名）—— 简单但全局污染风险大。

## 决策

1. **样式**：采用 **CSS Modules** —— 公共模式提取到全局 `index.css`（`.text-center-padded`、`.file-chip` 等），组件私有样式用 `.module.css`。
2. **前端拆分**：
   - AgentPage.tsx（1176 行）→ 拆为 `AgentChat/`（消息列表、输入区、审批弹窗、会话列表 4 个子组件 + 共享 hooks）。
   - ServerDetailPage.tsx（551 行）→ 监控/部署/环境配置/终端 4 个子组件已存在，提取到独立文件。
   - ExperimentRunPanel.tsx（539 行）→ 创建视图/运行视图拆为子组件。
   - LlmConfigForm.tsx（522 行）→ 配置组列表/配置组编辑表单拆为子组件。
3. **后端拆分**：
   - main.py（1631 行）→ 按业务域拆为 FastAPI APIRouter：`routes/papers.py`、`routes/agent.py`、`routes/servers.py`、`routes/experiments.py`、`routes/llm.py`、`routes/platforms.py`、`routes/search.py`、`routes/experiment_runs.py`。
   - database.py（1058 行）→ 按表拆为 `db/` 包：`db/papers.py`、`db/agent.py`、`db/experiments.py`、`db/search_history.py`、`db/innovations.py`、`db/reviews.py`、`db/experiment_runs.py`，共享 `_connect/_migrate` 留在 `db/__init__.py`。
4. **不做**：types.ts 不拆（411 行可维护）、api.ts 不拆（513 行可维护）、纯类型重排。

## 理由

- CSS Modules 是 Vite 原生支持的方案，零运行时、antd 兼容。
- FastAPI APIRouter 是官方推荐的模块化方式，路由注册在 `app.include_router()` 一行完成。
- 拆分边界按业务域，不按技术分层，与现有目录结构一致。

## 影响与后果

- 所有 import 路径变更，需全量回归（pytest + build + 冒烟）。
- CSS Modules 类名在 dev 模式带 hash，不影响功能但 DOM 类名变化。
- main.py 拆分后 app.py 的路由注册需按正确顺序（path 参数冲突如 /pdf vs /translation/pdf）。
