# 项目启动决策（产品与技术选型）

## 决策标题

确定 openlab 的产品形态、数据源、LLM 提供方、用户规模与首个开发模块。

## 元信息

- **日期**：2026-08-24
- **状态**：accepted
- **决策者**：用户
- **关联 Spec**：spec-001-paper-search-download（首个）

## 背景与问题

项目启动，需确定产品形态、数据源、LLM 提供方、用户规模与开发优先级。

## 备选方案

- 产品形态：Web 系统 / 本地 CLI / 桌面应用。
- 数据源：arXiv / Semantic Scholar / PubMed / Google Scholar 等。
- LLM：OpenAI 兼容 API / 本地模型 / 两者可配置。
- 用户规模：个人自用 / 小团队 / 开源社区通用。

## 决策

1. **产品形态**：Web 系统（前后端分离）。后端可运行在本地 Windows，通过 PowerShell 调用 SSH 连接远程服务器。
2. **论文数据源**：arXiv（首个数据源，后续可扩展）。
3. **LLM 提供方**：OpenAI 兼容 API（可切换 DeepSeek/通义/GPT 等）。
4. **用户规模**：个人自用，无需多用户/权限体系。
5. **开发优先级**：首个落地模块为「文献搜索与下载」。

## 理由

- Web 系统便于交互与展示科研流程；后端本地运行可借助 PowerShell 调用 SSH。
- arXiv 提供开放 API，最易实现且覆盖大量预印本。
- OpenAI 兼容 API 接口统一，便于切换不同模型。
- 个人自用可省去多用户/权限的复杂度，聚焦核心能力。
- 文献搜索与下载是后续分析、创新点设计的输入，按流程顺序优先开发。

## 影响与后果

- 技术栈：后端建议 Python + FastAPI，前端建议 React/Vue（待确认）。
- 无多用户体系，短期不实现登录鉴权。
- 后续模块依赖 spec-001 产出的文献数据。
