# spec-002 论文自动分析决策

## 决策标题

确定论文自动分析（spec-002）的分析维度、输入、范围、存储与语言。

## 元信息

- **日期**：2026-08-24
- **状态**：accepted
- **决策者**：用户
- **关联 Spec**：spec-002-paper-analysis

## 背景与问题

spec-001 已实现论文搜索与下载（PDF + 元数据入库）。spec-002 需在下载的论文上做自动分析，为后续创新点设计提供输入。

## 备选方案

- 分析维度：结构化总结 / 实验与结果 / 局限与展望 / 关键词标签（部分或全部）。
- 输入：仅标题+摘要 / 解析 PDF 全文。
- 范围：单篇 / 单篇+批量 / 含多篇对比综述。
- 存储：入库+前端+导出 / 仅返回 / 多格式导出。
- 输出语言：中文 / 英文 / 可切换。

## 决策

1. **分析维度**：结构化总结（研究问题/方法/贡献/结论）、实验与结果（数据集/基线/指标/关键结果）、局限与展望（局限性/未来工作）、关键词/标签，全部四项。
2. **输入**：解析 PDF 全文（非仅标题+摘要）。
3. **范围**：单篇分析 + 批量分析 + 多篇对比综述。
4. **存储**：分析结果入库 SQLite，前端详情展示，支持 Markdown 导出。
5. **输出语言**：可切换中/英（分析接口传入 language 参数）。

## 理由

- PDF 全文比摘要信息更完整，分析更准确（尤其方法与实验细节）。
- 全维度分析为后续创新点设计（spec-003）提供充分依据。
- 对比综述能帮助发现研究空白，是创新点的重要来源。
- 中/英切换兼顾个人可读性与开源通用性。

## 影响与后果

- 需引入 PDF 解析依赖（如 PyMuPDF）。
- 需新增 `analyses`、`reviews` 存储表。
- 需处理长文本与 LLM 上下文限制（分块/截断）。
- 复用 spec-001 的 LLM 配置（LangChain + OpenAI 兼容 + 平台预设）。
