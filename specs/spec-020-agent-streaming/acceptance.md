# Spec 020 验收清单

## 准备

1. 后端启动、前端启动；LLM 配置组已就绪（含 context_length 与思考强度）。
2. 已有若干历史 Agent 会话；至少一个可真实调用的模型。

## AC-1 流式输出与事件推送（FR-1 / FR-2 / FR-7）

- [ ] 发送消息后回复逐字实时出现（打字机效果），不再是长时间空白后一次性返回。
- [ ] 「思考中 / 执行中：工具名(第N步)」状态实时变化，无需轮询间隔感知。
- [ ] 工具调用完成后，对应气泡即时出现该工具卡片。
- [ ] 危险操作触发时审批弹窗经 WS 实时弹出；允许/拒绝后流程在同一连接继续直至 done。
- [ ] 对话期间浏览器 Network 无固定频率的详情轮询请求（旧轮询已移除）。

## AC-2 停止/中断（FR-4）

- [ ] 运行中显示「停止」按钮；点击后当前回复停止、状态变「已中断」。
- [ ] 中断后：`running=false`、status=interrupted；已生成的部分回复与工具记录保留，刷新页面仍在。
- [ ] 中断后可继续发送新消息正常对话。
- [ ] 同一会话运行中重复发送，前端提示运行中（后端 error 事件）。

## AC-3 上下文自动压缩（FR-5）

- [ ] 把所选模型 context_length 调小（或在长会话下）达到阈值后继续提问，能观察到「已压缩早期历史」提示，且对话仍连贯可引用早期要点。
- [ ] 压缩后会话消息结构为：系统提示 + 摘要 + 最近若干条；usage 输入 token 明显回落。
- [ ] 模型未配置 context_length 时从不触发压缩。
- [ ] 人为使摘要调用失败（如断网瞬间）时，本轮对话仍正常完成，仅跳过压缩。

## AC-4 复制与导出（FR-6 / FR-8）

- [ ] 单条 user/assistant 消息 hover 出现复制按钮，点击后剪贴板内容为该条 Markdown 原文并有已复制反馈。
- [ ] assistant 回复中的代码块右上角有复制按钮，复制内容为代码原文。
- [ ] 头部「导出 Markdown」下载 .md 文件：含会话名/时间/双方消息/工具摘要；含密钥场景下导出内容无明文凭据。

## AC-5 连接健壮性（NFR-1）

- [ ] 重启后端期间前端出现连接降级提示；后端恢复后自动重连并恢复可用（≤5 次退避内）。
- [ ] 切换会话立即切换通道与消息列表，无串扰。

## 回归

- [ ] 会话列表增删改查、重命名、删除清理沙箱均正常；token 用量与上下文占用百分比随对话更新。
- [ ] 论文搜索/分析/创新点/实验方案/服务器/终端等既有功能不受影响。
- [ ] 后端 `pytest tests -q` 全部通过；前端 `npm run build` 通过。
