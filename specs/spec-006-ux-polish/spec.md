# Spec：本地搜索过滤 + LLM 连通性测试 + 布局优化（spec-006）

## 元信息

- **Spec 编号**：`spec-006-ux-polish`
- **状态**：completed（已完成）
- **创建日期**：2026-08-24
- **负责人**：协调开发 Agent

## 背景与动机

三个 UX 优化：① 各页面快速本地过滤；② 设置页验证 LLM 配置是否连通；③ 修复论文库页底部多余空白导致的垂直滚动条。

## 目标

- 搜索页、论文库、历史页添加本地搜索框，快速过滤已加载数据。
- 设置页添加「连通性测试」，验证表单当前 LLM 配置能否连通。
- 减小论文库页分页器下方空白，避免垂直滚动条。

## 范围

### 包含（In Scope）

- 前端本地过滤（客户端即时，不重新请求）。
- 后端 `POST /api/llm/test` 连通性测试接口。
- 设置页连通性测试按钮与结果展示。
- 布局空白修复。

### 不包含（Out of Scope）

- 服务端搜索/过滤。
- 其它页面的连通性测试。

## 需求描述

### 功能需求

- FR-1：论文库页表格上方添加本地搜索框，按标题/作者即时过滤（大小写不敏感子串匹配）。
- FR-2：搜索页结果表格上方添加本地搜索框，按标题/作者即时过滤。
- FR-3：历史页「搜索历史」tab 按 query 过滤；「创新点历史」tab 按来源论文 arxiv_id 过滤（本地即时）。
- FR-4：设置页添加「连通性测试」按钮，用表单当前配置（base_url/api_key/model）测试 LLM 连通性，展示成功/失败与耗时。
- FR-5：修复论文库页分页器下方空白 margin，避免垂直滚动条。

### 非功能需求

- NFR-1：连通性测试不保存配置、不打印密钥、带超时保护。
- NFR-2：本地过滤纯客户端，不触发后端请求。

## 数据结构约定

连通性测试接口：

- `POST /api/llm/test`（body: base_url, api_key, model）→ 向 `{base_url}/chat/completions` 发送最小请求（如「ping」，max_tokens=1），返回 `{ok, message, latency_ms}`。配置项为空时返回明确错误。
