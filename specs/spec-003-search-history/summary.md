## 背景与目标

用户每次进入系统都要重复搜索，浪费时间。本 Spec 增加本地记录能力（搜索历史 + 结果快照 + 论文库自动加载），并改造 UI 为顶部导航栏 + 四页面布局。

## 功能需求清单（FR-1 ~ FR-11，全部完成）

历史记录：
- FR-1：前端启动自动加载已下载论文库。
- FR-2：关键词/主题搜索自动记录历史（query + mode + 结果快照 JSON）。
- FR-3：历史列表展示 query/mode/时间/结果数。
- FR-4：点击历史条目恢复结果快照。
- FR-5：删除单条 / 清空全部历史。
- FR-6：历史持久化到 SQLite，重启保留。

UI 改造（顶部导航栏 + 四页面）：
- FR-7：AntD Layout（Header + 水平 Menu + Content），品牌 + 页面切换。
- FR-8：搜索页（搜索表单 + 结果，LLM 配置移出）。
- FR-9：论文库页（已下载论文，启动加载，含分析/下载/综述操作）。
- FR-10：历史搜索页（列表 + 恢复/删除/清空）。
- FR-11：设置页（LLM 平台预设 + 自定义）。

非功能：NFR-1 单条快照上限 50 篇；NFR-2 密钥安全沿用。

## 后端接口

- `GET /api/search/history` — 历史列表（含 paper_count，不含完整 papers）
- `GET /api/search/history/{id}` — 单条快照（含 papers）
- `DELETE /api/search/history/{id}` — 删除单条
- `DELETE /api/search/history` — 清空全部
- 搜索自动记录历史（`/api/search`、`/api/search/topic`）

1. 分析模态框状态 tag 与按钮间距（Divider）。

4. 下载失败每篇重试 3 次（间隔 2s，可配置）。
5. 删除「分类」输入框。
6. 日期范围选择器中文（dayjs zh-cn）。
7. 「LLM 拆解检索式」提示改为搜索卡内联「已根据主题拆解为检索式：xxx」。
8. 表格改动落在共享 PaperTable，搜索页与论文库同步。

另有：删除死字段 `types.ts` 的 `SearchBase.category`；分析未下载论文的报错改为「该论文尚未下载，请先下载后再分析」。

## 使用方式

1. `.\start.ps1` 启动（后端 8001、前端 5174）。
2. 顶部导航切换：搜索 / 论文库 / 历史搜索 / 设置。
3. 搜索后自动记录历史；历史页点击可恢复快照。
4. 论文下载后操作列可「查看论文」；未下载时点「分析」会提示先下载。
